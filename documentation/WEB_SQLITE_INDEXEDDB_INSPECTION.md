# Inspecting CardNest web SQLite and IndexedDB

This guide explains how CardNest stores SQLite data in a browser and how developers can inspect it with browser DevTools and read-only SQL queries.

For the complete table inventory and relationships, see [`DATABASE_SCHEMA.md`](./DATABASE_SCHEMA.md). For SQLite initialization, migrations, and Android/Web architecture, see [`SQLITE.md`](./SQLITE.md).

## What is IndexedDB?

IndexedDB is the browser's built-in persistent database API. It stores JavaScript-friendly records in databases, object stores, and keys. It is asynchronous and can retain more structured data than cookies or `localStorage`.

IndexedDB is **not SQLite**:

| IndexedDB                                 | SQLite                                                             |
| ----------------------------------------- | ------------------------------------------------------------------ |
| Browser-native object database            | Relational SQL database                                            |
| Uses object stores and keys               | Uses tables, columns, indexes, and foreign keys                    |
| Queried with the IndexedDB JavaScript API | Queried with SQL                                                   |
| Does not provide SQL joins                | Supports joins, constraints, transactions, and `PRAGMA` statements |

CardNest does not model cards and transactions as ordinary IndexedDB objects. Instead, IndexedDB acts as the durable browser container for a serialized SQLite database.

## How CardNest combines IndexedDB and SQLite

The web storage path is:

```text
Angular features
  -> SqliteDatabase service
     -> @capacitor-community/sqlite web adapter
        -> <jeep-sqlite> web component
           -> sql.js / SQLite WebAssembly engine
              -> serialized SQLite database bytes
                 -> IndexedDB database: jeepSQLiteStore
```

While CardNest is running, `sql.js` executes real SQLite queries in memory. `jeep-sqlite` saves the SQLite representation into IndexedDB so it survives a refresh or browser restart.

This means:

- DevTools **Application > IndexedDB** can confirm that the stored SQLite representation exists.
- The IndexedDB viewer does not display `credit_cards`, `card_transactions`, or other SQLite tables as separate object stores.
- To inspect relational rows, query the live `<jeep-sqlite>` element from the DevTools Console.

## Before inspecting

1. Run CardNest in a browser.
2. Wait until the application has completely loaded.
3. Confirm that CardNest does not display the “SQLite storage is unavailable” warning.
4. Use synthetic development data whenever possible.
5. Do not inspect or share real card and transaction data on an untrusted computer.

The database name used by the application is `cardnest`.

## Viewing the IndexedDB container

In Chrome or Edge:

1. Open CardNest.
2. Press `F12` or use **Menu > More tools > Developer tools**.
3. Open the **Application** tab. It may be inside the `»` overflow menu.
4. In the left sidebar, expand **IndexedDB**.
5. Expand **jeepSQLiteStore**.
6. Expand its object stores and select the database record store.
7. Use **Refresh database** if the displayed record is stale.

Depending on the browser and `jeep-sqlite` version, the object-store names may differ. A CardNest record commonly includes a name such as `cardnestSQLite.db` and serialized database bytes.

The DevTools summary can show an IndexedDB version and object-store count. Those object stores are implementation details of `jeep-sqlite`; they are not CardNest's relational tables.

> **Do not choose “Delete database.”** That removes the browser's persisted CardNest database.

## Querying the live SQLite database

### 1. Open the Console

Open the **Console** tab while the CardNest page is selected. Ensure the console execution context is the main CardNest page rather than an extension or iframe.

Messages such as `runtime.lastError`, widget SDK warnings, or extension connection errors are usually generated by browser extensions and are unrelated to CardNest SQLite.

### 2. Find the jeep-sqlite element

Paste:

```js
await customElements.whenDefined('jeep-sqlite');
var cardNestSqlite = document.querySelector('jeep-sqlite');
cardNestSqlite;
```

The last expression should return an element resembling:

```html
<jeep-sqlite autosave="true"></jeep-sqlite>
```

If it returns `null`, see [Troubleshooting](#troubleshooting).

### 3. Confirm that the connection is open

```js
await cardNestSqlite.isDBOpen({
  database: 'cardnest',
  readonly: false,
});
```

Expected result:

```js
{
  result: true;
}
```

`readonly: false` selects the existing read/write connection that CardNest opened. It does **not** mean that an inspection query must modify data. Continue to use only `SELECT` and read-only `PRAGMA` statements.

If `readonly: true` is used, `jeep-sqlite` looks for a separate `RO_cardnest` connection. CardNest normally owns `RW_cardnest`, so the result can be `No available connection for cardnest`.

### 4. Create a reusable query helper

Paste this once per DevTools session:

```js
globalThis.cardNestQuery = async function (statement, values = []) {
  var result = await cardNestSqlite.query({
    database: 'cardnest',
    statement,
    values,
    readonly: false,
  });

  return result.values ?? [];
};
```

Test it:

```js
console.table(await cardNestQuery('PRAGMA user_version'));
```

The helper is temporary. Reloading or closing the page removes it.

## Listing SQLite tables

Using SQLite metadata:

```js
console.table(
  await cardNestQuery(`
    SELECT name
    FROM sqlite_master
    WHERE type = 'table'
      AND name NOT LIKE 'sqlite_%'
    ORDER BY name
  `),
);
```

Or using the component API:

```js
console.table(
  (
    await cardNestSqlite.getTableList({
      database: 'cardnest',
      readonly: false,
    })
  ).values,
);
```

## Inspecting columns, indexes, and relationships

Columns in a table:

```js
console.table(await cardNestQuery('PRAGMA table_info(card_transactions)'));
```

Indexes on a table:

```js
console.table(await cardNestQuery('PRAGMA index_list(card_transactions)'));
```

Columns used by a particular index:

```js
console.table(await cardNestQuery('PRAGMA index_info(idx_transactions_card_date)'));
```

Foreign keys:

```js
console.table(await cardNestQuery('PRAGMA foreign_key_list(card_transactions)'));
```

Original table-creation SQL:

```js
console.table(
  await cardNestQuery(`
    SELECT name, sql
    FROM sqlite_master
    WHERE type = 'table'
    ORDER BY name
  `),
);
```

Database integrity checks:

```js
console.table(await cardNestQuery('PRAGMA integrity_check'));
console.table(await cardNestQuery('PRAGMA foreign_key_check'));
```

`PRAGMA integrity_check` should normally return `ok`. `PRAGMA foreign_key_check` should normally return no rows.

## Viewing table data

Recent transactions:

```js
console.table(
  await cardNestQuery(`
    SELECT
      id,
      transaction_date,
      type,
      amount_minor,
      amount_minor / 100.0 AS amount,
      category_id,
      card_id
    FROM card_transactions
    ORDER BY transaction_date DESC, created_at DESC
    LIMIT 100
  `),
);
```

Cards:

```js
console.table(
  await cardNestQuery(`
    SELECT
      id,
      nickname,
      issuer_name,
      network,
      last_digits,
      archived,
      created_at,
      updated_at
    FROM credit_cards
    ORDER BY created_at
  `),
);
```

Categories and limits:

```js
console.table(
  await cardNestQuery(`
    SELECT
      category.id,
      category.name,
      category.applies_to,
      category.archived,
      limits.limit_minor / 100.0 AS monthly_limit,
      limits.show_limit
    FROM categories AS category
    LEFT JOIN category_limits AS limits
      ON limits.category_id = category.id
    ORDER BY category.name COLLATE NOCASE
  `),
);
```

Record counts:

```js
console.table(
  await cardNestQuery(`
    SELECT 'credit_cards' AS table_name, COUNT(*) AS records FROM credit_cards
    UNION ALL SELECT 'card_transactions', COUNT(*) FROM card_transactions
    UNION ALL SELECT 'categories', COUNT(*) FROM categories
    UNION ALL SELECT 'emi_plans', COUNT(*) FROM emi_plans
    UNION ALL SELECT 'emi_installments', COUNT(*) FROM emi_installments
    UNION ALL SELECT 'transaction_links', COUNT(*) FROM transaction_links
  `),
);
```

## Joining tables

Transactions with card and category names:

```js
console.table(
  await cardNestQuery(`
    SELECT
      transaction.transaction_date,
      transaction.type,
      transaction.amount_minor / 100.0 AS amount,
      card.nickname AS card,
      card.last_digits,
      category.name AS category
    FROM card_transactions AS transaction
    LEFT JOIN credit_cards AS card
      ON card.id = transaction.card_id
    LEFT JOIN categories AS category
      ON category.id = transaction.category_id
    ORDER BY transaction.transaction_date DESC, transaction.created_at DESC
    LIMIT 100
  `),
);
```

Transactions made with Cash, Bank/UPI, or a meal card can have `card_transactions.card_id = NULL`. Their application source identifier remains in the JSON `payload.cardId` field because the current foreign key references only `credit_cards`.

Linked refunds and adjustments:

```js
console.table(
  await cardNestQuery(`
    SELECT
      link.relationship_type,
      link.transaction_id AS linked_transaction_id,
      linked.amount_minor / 100.0 AS linked_amount,
      link.related_transaction_id AS original_transaction_id,
      original.amount_minor / 100.0 AS original_amount
    FROM transaction_links AS link
    JOIN card_transactions AS linked
      ON linked.id = link.transaction_id
    JOIN card_transactions AS original
      ON original.id = link.related_transaction_id
    ORDER BY link.created_at DESC
  `),
);
```

EMI schedules:

```js
console.table(
  await cardNestQuery(`
    SELECT
      plan.id AS plan_id,
      plan.status,
      installment.installment_number,
      installment.statement_date,
      installment.due_date,
      installment.principal_minor / 100.0 AS principal,
      installment.interest_minor / 100.0 AS interest,
      installment.paid
    FROM emi_plans AS plan
    JOIN emi_installments AS installment
      ON installment.emi_plan_id = plan.id
    ORDER BY plan.id, installment.installment_number
  `),
);
```

## Using parameters safely

Pass user-supplied search values separately from the SQL text:

```js
console.table(
  await cardNestQuery(
    `SELECT id, name, applies_to
     FROM categories
     WHERE lower(name) LIKE lower(?)
     ORDER BY name`,
    ['%food%'],
  ),
);
```

Question-mark placeholders prevent the value from being interpreted as SQL syntax.

## Inspecting JSON payloads

Several tables store the full TypeScript domain object in a `payload` JSON string alongside normalized columns.

Fetch and parse transaction payloads in JavaScript:

```js
var transactionRows = await cardNestQuery(`
  SELECT id, transaction_date, amount_minor, payload
  FROM card_transactions
  ORDER BY transaction_date DESC, created_at DESC
  LIMIT 50
`);

var parsedTransactions = transactionRows.map(function (row) {
  var payload = JSON.parse(row.payload);

  return {
    id: row.id,
    date: row.transaction_date,
    amount: row.amount_minor / 100,
    merchant: payload.merchant,
    sourceId: payload.cardId,
    categoryId: payload.categoryId,
    notes: payload.notes,
    taxIncluded: payload.taxIncluded,
    taxAmount: payload.taxMinor ? payload.taxMinor / 100 : undefined,
    relatedTransactionId: payload.relatedTransactionId,
    emiPlanId: payload.emiPlanId,
    attachments: payload.attachmentIds,
  };
});

console.table(parsedTransactions);
```

Inspect one full object:

```js
console.dir(JSON.parse(transactionRows[0].payload));
```

If the SQLite WebAssembly build includes JSON1, JSON fields can also be queried with `json_extract`:

```js
console.table(
  await cardNestQuery(`
    SELECT
      transaction_date,
      amount_minor / 100.0 AS amount,
      json_extract(payload, '$.merchant') AS merchant,
      json_extract(payload, '$.notes') AS notes
    FROM card_transactions
    ORDER BY transaction_date DESC
  `),
);
```

If SQLite reports `no such function: json_extract`, parse payloads in JavaScript instead.

## Why TypeScript examples fail in the Console

Chrome and Edge DevTools execute JavaScript, not TypeScript. This application-code example cannot be pasted into the Console:

```ts
const rows = await database.query<Record<string, unknown>>('SELECT ...');
```

It fails with an error such as:

```text
Uncaught SyntaxError: Missing initializer in const declaration
```

There are two reasons:

1. `<Record<string, unknown>>` is a TypeScript generic and is invalid JavaScript syntax.
2. Angular's injected `database` service is not exposed as a browser global.

Use the JavaScript `cardNestQuery()` helper from this guide instead:

```js
var rows = await cardNestQuery('SELECT * FROM card_transactions LIMIT 100');
console.table(rows);
```

## Troubleshooting

### `cardNestSqlite` is `null`

- Confirm this is the web build, not an unrelated page.
- Wait for the application to finish loading.
- Run `await customElements.whenDefined('jeep-sqlite')` before querying the element.
- Inspect `document.querySelectorAll('jeep-sqlite')`; CardNest should have one host element.

### `isDBOpen()` returns `false`

- Reload CardNest.
- Check for the application storage warning.
- Inspect Console errors from application startup.
- Confirm the database name is exactly `cardnest`.

### `No available connection for cardnest`

- Use `readonly: false` on `isDBOpen()`, `query()`, and `getTableList()`.
- Do not call `createConnection()` or `open()` yourself. The application owns the connection.
- Reload the application if a previous failed restore or manual experiment closed the connection.

### `cardNestQuery is not defined`

Run the helper setup again. Console variables disappear after a reload.

### `no such table`

Check the applied migration version:

```js
console.table(await cardNestQuery('PRAGMA user_version'));
```

Then check CardNest startup errors. A migration may not have completed.

### Queries show stale data

- Query the live connection rather than relying only on the IndexedDB viewer.
- Wait for the application write to finish.
- Use **Refresh database** in the Application panel.
- Reload CardNest only after pending changes have completed.

## Safety rules

Use only:

- `SELECT` statements;
- read-only `PRAGMA` statements such as `table_info`, `index_list`, `foreign_key_list`, `integrity_check`, and `user_version`.

Do not use from DevTools:

- `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, or `VACUUM`;
- `run()` or `execute()`;
- `deleteDatabase()`;
- `importFromJson()`;
- manual `createConnection()`, `open()`, or `close()` calls.

Manual changes bypass CardNest's Angular signals and persistence commands. The screen may continue showing old state, later application writes may overwrite the manual change, and invalid relationships can damage the database.

Do not display or copy `card_secrets`, full preference values, or complete card payloads from a real account. Even encrypted values and key material should be treated as sensitive.

## Backups are different

An encrypted `.cnbak` file is not the IndexedDB database and is not a directly readable SQLite file. It is an encrypted CardNest export protected by the user's backup passphrase. Use CardNest's Restore workflow to read it.

The Console inspection process in this guide queries only the currently open web database. It does not decrypt or inspect `.cnbak` files.
